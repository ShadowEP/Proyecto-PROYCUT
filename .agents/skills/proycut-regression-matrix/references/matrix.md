## Notas de uso

- "Prueba pura" siempre significa: invocar la función con datos de entrada conocidos y verificar la salida manualmente (a mano o con un script desechable en el scratchpad), nunca un test runner que no existe en este repositorio.
- Cuando el subsistema toca varios módulos a la vez (por ejemplo, un cambio en piezas que afecta validación, geometría y costos), aplicar las filas correspondientes a cada módulo, no solo la más obvia.
- Si una fila indica una prueba manual y no hay forma de ejecutarla en la sesión actual (sin navegador), decirlo explícitamente en el reporte final en vez de omitirla o darla por hecha.
